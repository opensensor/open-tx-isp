# Module size switches

Build switches that keep the `tx-isp-<soc>.ko` modules small, what each
one does, and how to get the old build back. The size table of the vendor
modules, RC1 and the current state is in the OpenIMP repository,
`docs/SIZE.md`.

## Export whitelist (T31)

`tx-isp-t31.ko` exported 328 symbols; other modules use 27 of them.
`driver/t31/tx_isp_t31_exports.h` lists the exported ones; every other
`EXPORT_SYMBOL` in the driver becomes a plain declaration
(`include/tx_isp_kernel_compat.h`), so `--gc-sections` drops the exported
functions nothing references.

- `driver/isp_imports.txt`: the symbols each SoC module must export,
  generated by `tools/scan_isp_imports.py` from the undefined symbols of
  every `.ko` in the thingino outputs (sensors, avpu, audio, motor, ...)
  and from the ingenic-sdk, `sensor-src` and avpu sources.
- `tests/check_isp_exports.sh` fails the T31 Kbuild (an `always` target)
  and `build_local.sh` (all SoCs) when a module does not export a symbol
  from that list.
- A new module that needs another symbol: add it to
  `tx_isp_t31_exports.h` and `driver/isp_imports.txt`.
- `TX_ISP_T31_EXPORT_ALL=y` builds the old full export table.

The other SoCs export at most 14 symbols nobody imports (under 2 KB), so they
keep their export tables; the check runs for them too.

## T31 runtime (review #223)

- The ISP IRQs (isp-m0, isp-w02) have no thread handler: no idle
  `irq/NN-isp-*` kthreads (the top halves finish all work).
- `/proc/jz/isp/isp-m0` "ch0 done" counts channel 0 completions once per
  frame (was about 2x: VIC frame done and core drain both counted).
- `tx_isp_tuning.o` stays without `-fdata-sections`: 580 B of dead data
  left, the flag costs about +17 KiB of anchor code there.
- Kept on purpose (vendor behaviour): the fw thread's 200 ms idle timeout
  (OEM 20 jiffies) and event dispatch with local IRQs off.

## Section garbage collection and anchors (T10, T20)

T10 and T20 now build like T21/T23/T31/T41: `-ffunction-sections`,
`--gc-sections` with `driver/tx_isp_merge.lds` (`TX_ISP_GC=n` restores the
old layout) and `-fsection-anchors`. Section anchors reorder the static
data of a translation unit, so the recovered Apical firmware unit
(`tx_isp_t20_firmware.c`, also built for T10) is compiled without them and
keeps the data layout `tests/t20_fw` verified (`nm` layout identical to a
build without anchors). `TX_ISP_FW_ANCHORS=y` includes it.

## Heap: large CPU-only tables from vmalloc (T10, T20, T21)

Tables only the CPU reads (copied into the ISP by register writes or into
an skb) come from vmalloc, so they no longer take power-of-two kmalloc
blocks: T10/T20 image tuning state (16.3 KiB, was 32 KiB), IQ parameter
manager, IQ bin copy and firmware tables (8.9 + ~60 + ~30 KiB, were
16 + 64 + 32 KiB); T21 tuning state (0x40d0) and netlink reply buffer
(0x10018, was an order-5 block per `tisp_init`). DMA targets stay
physically contiguous; the T21 statistics buffers use `alloc_pages_exact`
(the 24 KiB AE buffer no longer holds 32 KiB). Device A/B 2026-11-06:
VmallocUsed +92..+132 kB while streaming, no change in ISP interrupt rate.

## Bring-up parameters (T23, T41)

Parameters that only served the bring-up (experiment switches, diagnostic
counters) are built in only on request; the variables keep their default
values, so the default behaviour does not change. A parameter is in this
group when no document, tool, test, script, OpenIMP or firmware file
reads or sets it (searched 2026-10-11). The vendor parameters
(`isp_clk*`, `clk*_name`, `isp_memopt`, `direct_mode`, `ivdc_*`,
`isp_ch*`, `print_level`, ...), the documented ones and the T41 V4L2
settings always stay. Passing a removed parameter to `insmod` only logs
"unknown parameter ignored".

- T23: `TX_ISP_T23_BRINGUP_PARAMS=y` builds them in; default: left out
  (115 parameters).
- T41: `TX_ISP_T41_BRINGUP_PARAMS=n` (default since 2026-10-24) leaves them out
  (83 parameters, 41 KB of module file, 15 KB xz and 34 KB of RAM);
  `=y` builds them in (diagnostic scripts such as tools/rawchart/t41_isr_stages.sh
  read some). It was `y` while the module-reload heap overwrite was open; that
  bug has not been seen again in 70+ load/unload cycles. `TX_ISP_T41_TMO_SELFTEST=y`
  builds the `t41_tmo_map_selftest` parameter (off by default, 8 KB).

## Bring-up parameters and debug proc (T40)

Same scheme as T23/T41, on the single-file T40 recovered driver
(`t40_bringup_param*` macros in `tx_isp_t40_recovered.c`):
`TX_ISP_T40_BRINGUP_PARAMS=n` (default since 2026-10-24) leaves out 340 of the
548 parameters: every one whose name appears in no tool, script, test, doc,
OpenIMP, firmware or audit file (searched 2026-10-24). The vendor
parameters (`isp_dual_buf`, `isp_ch0_pre_dequeue_time`, `isp_memopt`,
`isp_clk`, `clk_name`, `print_level`) always stay. `TX_ISP_T40_DEBUG_PROC=n`

reads can block while streaming, `tools/t40_safe_qbuf_dump_probe.sh` already
skips it); `=y` brings back the register dump, `echo exit N` and `echo dumplog`.

## Log prefixes (T23, T41)

The kernel log lines start with `t23: ` and `t41: ` (`pr_fmt` for the
`pr_*` calls, the same prefix in the `printk` format strings) instead of
`tx_isp_t23_recovered: `, `tx_isp_t41_recovered: `, `tx_isp_t41: ` and
`tx-isp-t41: `. The T23 trace filter matches the new prefix.

## Dead ISR chain and event queues (T23, Lu-Fi/openimp#224)

The hand-written `isp_irq_handle` dispatches the core status bits itself and
the ISP lines have no thread_fn, so core ops +0x20/+0x24 stay NULL; the
recovered `ispcore_interrupt_service_routine` / `ispcore_irq_thread_handle`
and everything only they call are no longer linked. `tisp_event_push` drops
events without touching `tisp_event_queues` (never initialised, never
drained), which removes that 7.7 KB .bss. Module RAM 868393 -> 857173 B.
If a stock event thread or the stock core ISR is ever wired up again, both
have to come back together (`tisp_event_init` caller + queue path in
`tisp_event_push`, core ops +0x20/+0x24).

## Open (not changed)

- **T21 day/night parameter copies (`tparams_day`, `tparams_night`, 2 x
  85 KB).** Not reloaded from the tuning file on a switch: after a switch
  the 256 parameter pointers in `tparams` point into the active
  `tparams_day`/`tparams_night` array (the switch copies the whole block,
  pointer table included), so the firmware reads and writes its parameters
  there, and tuning writes such as the custom-effect gains go straight into
  `tparams_day`. Reloading from the file would drop those changes at every
  switch. A smaller, layout-preserving variant (one shared 26 KB prefix
  instead of three) still touches every `tparams_day + offset` access.
  Needs a write-path audit and day/night device tests first.
- **T23 `oem_IspAeStatic` / `IspAeStatic` (2 x 16 KB).** The lifted stock
  AE0 (`source_ae_oem=1`, default) keeps its own copy; the recovered
  statistics, histogram and zone readers (`tisp_ae0_get_statistics`,
  `tisp_ae_get_y_zone`, ...) use the other. Sharing one buffer changes what
  those readers return unless they are proven idle with the lifted AE.
- **T30 at -O0.** `-Os` with `--gc-sections` would shrink the module from
  845 to 342 KB (RAM 677 to 289 KB), but there is no host equivalence
  harness for the T30 recovered driver (like `tests/t20_fw`) and no T30
  test camera. The layout-only part (`-ffunction-sections`,
  `--gc-sections`, `-x`, `-mno-pdr`, still `-O0`) gives 673 KB (RAM 574
  KB) without changing code generation.
